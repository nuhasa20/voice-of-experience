# Voice of Experience (صوت الخبرة)

**Voice-first engineering knowledge preservation for industrial troubleshooting in oil & gas facilities.**

---

## Overview & Target Audience

In upstream and midstream oil & gas operations, high-value diagnostic knowledge is often trapped in informal phone calls, field voice notes, or senior operator intuition. Traditional computerized maintenance management systems (CMMS) can contain sparse, sanitized records that fail to convey the subtle operational reasoning needed to troubleshoot complex equipment and data anomalies.

**Voice of Experience (صوت الخبرة)** is built for **data analysts, production engineers, and plant operators** working in industrial oil & gas environments. It provides a voice-first workflow to record, transcribe, structure, verify, and retrieve operational troubleshooting notes spoken in natural Libyan Arabic dialect mixed with English technical terms.

---

## The Problem

When production anomalies occur—such as sensor drift masquerading as well drawdown, deep learning models failing on rare fault distributions, or models performing well on simulators but collapsing on real field data—junior engineers and data analysts often lack access to experienced mentors. LLM-based solutions can hallucinate plausible-sounding but hazardous advice in safety-critical industrial settings.

---

## How It Works

Voice of Experience enforces an end-to-end, safety-conscious workflow:

1. **Audio Capture (Voice Note or Upload)**
   - Speak naturally in Libyan Arabic dialect interspersed with English technical engineering terms (up to 2 minutes / 10 MB).
   - Alternatively, upload existing `.ogg`, `.webm`, `.wav`, or `.mp3` voice recordings.
2. **Verbatim Transcript Review & Dialect Correction**
   - Resilient speech-to-text pipeline transcribes the audio.
   - The user reviews the exact verbatim transcript and resolves any flagged `[unclear]` tokens directly in the editor before structured extraction.
3. **5-Field Structured Diagnostic Card**
   - AI extracts five operational fields:
     - **Problem Summary**
     - **Possible Causes**
     - **Verification Checks**
     - **Solution Steps**
     - **Cautions & Warnings**
4. **Code-Enforced Verbatim Quote Verification**
   - Pure Python string normalization and substring matching verifies that every verbatim quote extracted by the model appears literally in the reviewed transcript.
   - The summary text for each field is generated by the model and is **not** independently verified against the transcript.
   - Any quote containing unresolved `[unclear]` markers is strictly rejected by the verification engine.
5. **Human Expert Approval**
   - The card cannot be added to the searchable knowledge library until the expert checks an approval box (no identity authentication is performed).
6. **Search with an Honest "I Don't Know"**
   - Users search by symptoms or equipment behavior using Arabic or English technical phrasing.
   - The retrieval engine uses character n-gram TF-IDF cosine similarity, intended to tolerate dialectal spelling variations and transliterated technical terms (not evaluated separately).
   - When the best matching score falls below the calibrated similarity threshold ($\tau = 0.19$), the system refrains from generating unverified text and presents the honest fallback panel:
     > *"I don't know — no expert has covered this yet."*
     > *"We only show answers recorded and approved by an expert."*

## Real vs Demo Labels

Every card in the current library is tagged **`Demo`** (illustrative scenarios based on problems the author met while developing a hypothetical oil & gas ML project, plus scripted scenarios read by volunteer speakers). None is a plant operating record, and no card comes from a field deployment.

The **`Real`** tag exists in the application for future recordings contributed by actual practitioners and is not used by any current card in the library.

In the user interface, labels are rendered in the following places:
- **Diagnostic Cards**: Displayed as a metadata pill (`[Demo]`) on each card in the search results and card library grid.
- **Search Suggestions**: Displayed as a pill badge next to matching note titles in the search autocomplete dropdown.
- **Contribution Setup**: Displayed as selectable radio options under *Origin Classification* when recording a new note.

## How to Run

### Prerequisites
- Python 3.10+
- No separate `ffmpeg` install required — audio conversion uses [`imageio-ffmpeg`](https://github.com/imageio/imageio-ffmpeg), which bundles its own ffmpeg binary and is installed automatically via `requirements.txt`.

### 1. Clone & Set Up Virtual Environment

```bash
git clone https://github.com/nuhasa20/voice-of-experience.git
cd voice-of-experience
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 2. Configure Environment Variables

Copy `.env.example` to `.env` and insert your API keys:

```bash
cp .env.example .env
```

Open `.env` and fill in:
- `GEMINI_API_KEY`: Google Gemini API key (for primary STT and card extraction).
- `GROQ_API_KEY`: Groq API key (for Whisper fallback STT).

### 3. Run the Application

```bash
uvicorn server.main:app --host 127.0.0.1 --port 8000
```

Open your browser at `http://127.0.0.1:8000`.

## Running Tests

The test suite validates database integrity, audio conversion, transcription pipelines, quote verification algorithms, search ranking, and save-flow guards. The tests use stubbed providers (no real STT/LLM calls) and there are no browser tests:

```bash
python3 -m pytest tests/ -v
```

## Search Evaluation Results

Search performance is evaluated using `scripts/eval_search.py` on `eval/queries.json`.

> **Note**: Evaluated against the author's 7-card library. During final testing an extra recording of an existing scenario was added, which temporarily dropped tuning to 7/10 because that same-topic card took top-1 for T1 and T7; it was removed as a duplicate, restoring the original 7-card library. This is a small, author-written evaluation set and is not evidence of generalization.

- **Tuning Split (10 queries, τ = 0.19)**:
  - **9/10 passed (90.0%)** at calibrated threshold $\tau = 0.19$, tuned on only these 10 queries.
  - **T9** is the only failure (false positive: out-of-corpus near-domain negative *"المضخة الغاطسة حرارة المحرك مرتفعة، ايش السبب"* scored 0.2670, above threshold $\tau = 0.19$).
  - In-scope query scores are close to $\tau$: minimum top score is 0.1964 (query **T1**), and query **T7** scored 0.1997, both just above the threshold.
- **Held-Out Split (7 queries)**:
  - **7/7 passed (100%)**, evaluated in a single run on the same 7-card library with no post-hoc threshold adjustment.
  - Prior to the held-out run: query **H4**'s ground truth was updated when a matching card (`card_11b4100a67b8`) was added; query **H7** (a near-domain negative) was also added to the held-out set.
  - This is a small author-written set; the 100% result should not be read as evidence of generalization. Note that in-scope scores are close to $\tau$ (minimum 0.1964) and $\tau$ was tuned on only 10 queries.

To re-run evaluation:
```bash
python3 scripts/eval_search.py --split tuning
python3 scripts/eval_search.py --split heldout
```

## Limitations

- **Not Validated with Engineers**: Not validated with practicing oil & gas engineers.
- **Contributor Checkbox Approval**: Expert approval is a checkbox by the contributor (no identity or qualification authentication is performed).
- **Near-Duplicate Ranking Competition**: Near-duplicate cards on the same topic compete for top-1 (no deduplication).
- **Internet & Free-Tier Quotas**: Requires an active internet connection to communicate with Gemini and Groq API endpoints. Free-tier accounts may be subject to rate limits during peak usage.
- **Small Corpus Size**: The proof-of-concept corpus is small; search quality degrades on queries outside the covered topics.
- **STT Fallback Chain**: Speech-to-text relies on a cascade (`gemini-3.8-flash` $\rightarrow$ `gemini-3.5-flash` $\rightarrow$ Groq `whisper-large-v3`). In the event of network disruption or concurrent rate limits across all providers, transcription will fail gracefully with a descriptive error.
- **Browser Compatibility**: Google Chrome is recommended for audio recording to guarantee standard `MediaRecorder` WebM/Opus support.
